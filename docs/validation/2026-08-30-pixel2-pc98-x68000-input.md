# Pixel2 PC-98 / X68000 input validation

Date: 2026-08-30

## NP2kai

The upstream NP2kai default, `np2kai_joymode = "OFF"`, does not translate
Pixel2 RetroPad events for keyboard-driven PC-98 software. Following the proven
plumOS handheld policy, the factory core options now contain:

```ini
np2kai_joymode = "Arrows 3button"
```

This maps the D-pad to PC-98 cursor keys, A/B/X/Y through the three-button
keyboard profile, SELECT to Escape, and START to Return. The config merge adds
the option only when it is absent and preserves user-selected modes such as
Mouse.

The operator confirmed that PC-98 content starts through the frontend route.
Machine checks passed startup, non-black scanout, and advancing ALSA playback.
Final physical acceptance of the newly added Pixel2 input mapping remains open.

## PX68k

The freely distributed X68000 version of Cho Ren Sha 68K v1.10 was used as test
content.

- Test content: `CH68_110.xdf`
- Source: `https://yosshin4004.github.io/x68k/crs68k/official/index.html`
- SHA-256: `6d8169ef89654fd7986b65eecfb5444dc496ac8e2f888b385a6b531ea3ef2146`
- Device path: `/mnt/plumos-user/roms/X68000/CH68_110.xdf`
- Core: `px68k_libretro.so`

The XDF was placed only on the user partition; it is not part of the repository,
app layer, or release image. PX68k started through the frontend route. Machine
checks passed startup, non-black scanout, and advancing ALSA playback, and a DRM
capture showed the game loading resources after Human68k startup. The operator
then confirmed game startup and physical controls on the device.

Machine checks alone do not establish audible quality, orientation/aspect/color,
exit behavior, or save/load behavior.
