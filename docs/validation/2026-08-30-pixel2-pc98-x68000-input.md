# Pixel2 PC-98 / X68000 input validation

Date: 2026-08-30

## NP2kai

The upstream NP2kai default, `np2kai_joymode = "OFF"`, does not translate
Pixel2 RetroPad events for keyboard-driven PC-98 software. The Pixel2 factory
core options now contain:

```ini
np2kai_joymode = "Arrows 3button"
```

This maps the D-pad to PC-98 cursor keys, A/B/X/Y through the three-button
keyboard profile, SELECT to Escape, and START to Return. The device already had
a generated `config/Neko Project II kai/Neko Project II kai.opt`, however, and
its `OFF` value took precedence over the global core options. The normal config
merge could not repair an existing SD card, which was the direct cause of the
input failure.

Commit `4948bb5` checks this per-core option before every NP2kai launch. Once per
installation, an exact legacy `OFF` value is migrated to `Arrows 3button` and
the original file is backed up. Existing user choices such as `Mouse` are
preserved, and a deliberate `OFF` selection after migration is not changed.

A diagnostic core recorded the RetroPad bits directly. Physical UP reached
NP2kai as `0x0010`, DOWN as `0x0020`, A as `0x0100`, B as `0x0001`, and L2 as
`0x1000`. After selecting `Mouse`, the operator confirmed restored D-pad and
game controls. The diagnostic core was removed, and the managed
`/mnt/plumos/cores/np2kai_libretro.so` started with the same option. The frontend
component passed 200/200 checksums, the complete app layer passed 11333/11333,
and the user option file retained the same SHA-256 across deployment.

Machine checks also passed startup, non-black scanout, and advancing ALSA
playback. Audible quality and normal exit still require physical acceptance.

## PX68k

The freely distributed X68000 version of Cho Ren Sha 68K v1.10 was used as test
content.

- Test content: `CH68_110.xdf`
- Source: `https://yosshin4004.github.io/x68k/crs68k/official/index.html`
- SHA-256: `6d8169ef89654fd7986b65eecfb5444dc496ac8e2f888b385a6b531ea3ef2146`
- Device path: `/mnt/plumos-user/roms/X68000/CH68_110.xdf`
- Core: `px68k_libretro.so`

The XDF was placed only on the user partition; it is not part of the repository,
app layer, or release image. PX68k started through the frontend route. Machine
checks passed startup, non-black scanout, and advancing ALSA playback, and a DRM
capture showed the game loading resources after Human68k startup. The operator
then confirmed game startup and physical controls on the device.

Machine checks alone do not establish audible quality, orientation/aspect/color,
exit behavior, or save/load behavior.
