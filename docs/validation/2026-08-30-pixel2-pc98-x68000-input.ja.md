# Pixel2 PC-98 / X68000入力検証

日付: 2026-08-30

## NP2kai

NP2kai上流の既定値`np2kai_joymode = "OFF"`では、RetroArchがPixel2の
RetroPad入力を受信してもkeyboard-driven PC-98 contentへ入力が渡らない。
Pixel2のfactory core optionには次を追加した。

```ini
np2kai_joymode = "Arrows 3button"
```

この設定では十字キーをPC-98 cursor key、A/B/X/Yを3-button keyboard
profile、SELECTをEscape、STARTをReturnへ変換する。ただし実機には
`config/Neko Project II kai/Neko Project II kai.opt`が既に生成されており、
その`OFF`がglobal core optionより優先されていた。通常のconfig mergeだけでは
既存SDを修復できないことが、今回の操作不能の直接原因だった。

commit `4948bb5`はNP2kai起動前にこのper-core optionを検査する。一度だけ、値が
厳密に`OFF`の既存設定を`Arrows 3button`へ移行し、移行前ファイルを退避する。
既に`Mouse`などを選択済みの場合は値を保持し、移行後にユーザーが`OFF`を選んだ
場合も再変更しない。

入力診断coreではRetroPad bitを直接記録し、物理UP=`0x0010`、DOWN=`0x0020`、
A=`0x0100`、B=`0x0001`、L2=`0x1000`がNP2kaiまで届くことを確認した。
`Mouse`選択後、operatorが十字キーとゲーム操作の復旧を確認した。診断coreは削除し、
同じ設定を正式な`/mnt/plumos/cores/np2kai_libretro.so`で起動できること、frontend
component 200/200とapp-layer 11333/11333のchecksum合格、ユーザー設定のSHA不変を
確認した。

機械検査は起動、非黒画面、ALSA playback pointer進行に合格している。音質と通常終了の
最終判定は物理実機で行う。

## PX68k

配布元が明確なフリーソフト「超連射68k」v1.10のXDFを検証用に使用した。

- Test content: `CH68_110.xdf`
- Source: `https://yosshin4004.github.io/x68k/crs68k/official/index.html`
- SHA-256: `6d8169ef89654fd7986b65eecfb5444dc496ac8e2f888b385a6b531ea3ef2146`
- Device path: `/mnt/plumos-user/roms/X68000/CH68_110.xdf`
- Core: `px68k_libretro.so`

XDFはユーザーパーティションへだけ配置し、repository、app-layer、release imageには
収録しない。FE経路でPX68kを起動し、機械検査で起動、非黒画面、ALSA playback
pointer進行に合格した。DRM captureではHuman68k起動後にゲームresourceを読み込む
画面を確認した。最後にoperatorがゲームの起動と物理操作を実機で確認し、合格とした。

機械検査だけでは音質、画面方向・比率・色、終了操作、save/loadを判定しない。
