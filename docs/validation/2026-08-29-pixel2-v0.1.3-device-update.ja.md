# Pixel2 v0.1.3実機アップデート検証

日付: 2026-08-29

実機: `192.168.10.107`のGKD Pixel2

## 更新前状態

実機は公開版v0.1.2ではなく、N64入力の最終acceptance Runtimeで動作していました。

```text
Runtime: 0.1.2-dev-96f3af5
Kernel:  5.10.198
FE ready: yes
pending request: none
pending Runtime: none
last result: runtime_healthy
```

更新前に11,328件の全管理対象を読み取り、Runtime検証に合格しました。実機のchecksum
indexはread-onlyで取得しました。

```text
runtime_verify=result-ok
checksums.sha256:
b61a2d1c4e5024e19567188882714b1fd5980fab956f5ae0a2a09ec20242f5af
```

公開版v0.1.2用packageはdevelopment Runtimeへ強制適用していません。取得したchecksum
indexから正式v0.1.3 app layerへの実機専用transitionを生成し、公開用packageは変更せず
保持しました。

hostでEd25519署名を検証しました。archiveは隠し一時名で転送し、実機側SHA-256、`sync`、

Pixel2の通常safe rebootはfrontendを停止し、user volumeを正常にunmountしました。
updaterはboot中にtransactionを適用し、frontend ready marker作成後だけhealthyへ昇格しました。

## Runtime smoke

device media validatorで`N64/SUPERMARIO64.Z64`を
`standalone:mupen64plus`から10秒間起動しました。

```text
startup=pass
screen=pass
audio=pass
battery=62%
```

captureした640x480 logical frameは正しい向きで、想定した4:3表示を維持しています。
ALSA playbackも進行しました。終了後は起動専用cacheとemulator processが残らず、
frontend 1 processへ復帰しました。package内`RiceVideoLinux.ini`もSHA-256
`ec89fe5ab5760b94b822b41dc2889afc280a138fe1cb43811e1346b539850be9`を維持しました。
最後のDRM readbackでは通常の6-system frontend grid、Wi-Fi、battery表示を確認しました。

healthy昇格と証跡取得後、実機専用transition archiveだけをupdate inboxから削除しました。
local証跡は`output/live/2026-08-29-pixel2-v0.1.3-device-update/`へ保持しています。
公開用の署名済みv0.1.2-to-v0.1.3 updateはrelease assetのままです。

## acceptance境界

正式v0.1.3 Runtime payload、transactional update、全管理file readback、mutable data保持、
frontend/Wi-Fi復帰、standalone N64の起動・表示・音声をPixel2実機で確認しました。
物理Function切替、操作、終了、SRAM loadは直前の同一機能Runtimeでoperator合格済みです。
このupdate-only試験では新規SD imageへの書き込みは行っていません。
