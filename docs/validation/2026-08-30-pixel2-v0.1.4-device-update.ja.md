# Pixel2 v0.1.4実機updateとRockbox検証

日付: 2026-08-30

実機: `192.168.10.107`のGKD Pixel2

## 更新前状態

実機は公開v0.1.3 Runtimeではなく、先にacceptance済みのPortMaster修正版で動作していた。

```text
Runtime: 0.1.3-dev-1d1195e
Kernel: 5.10.198
source_ref: 1d1195e
request: absent
pending Runtime: absent
checksums.sha256:
2c41592f936d6828dbed20626ab9c73a0633747f743bfe5fb25550c805b6db36
runtime_verify=result-ok
```

公開v0.1.3-to-v0.1.4 packageはdevelopment Runtimeへ強制適用していない。実機のchecksum
indexをreadbackし、正式v0.1.4 app layerへの実機専用署名transitionを生成した。

```text
source_version: 0.1.3-dev-1d1195e
version: 0.1.4
package SHA-256:
3dbd8165e894964fda8ab89152e0886b1b9cf6e155850ad8953d93987f3e0b61
payload files: 50
deleted files: 0
payload bytes: 44669479
```

packageをhostで検証し、隠し一時名で転送、実機SHA-256、`sync`、atomic rename、rename後
SHA-256の順に確認してproduction updaterへ渡した。通常safe rebootはfrontendを停止し、
`/roms`とuser volumeを正常にunmountしてから再起動した。

## Rockbox検証

`/mnt/plumos-user/roms/PORTS/Rockbox.sh`をproduction
`plumos-portmaster-port-launch`経路から起動した。frontendがdisplay ownershipを解放し、
launcher、Rockbox本体、GPTokeYB2 processが起動した。

active DRM planeをcaptureし、正しい向きの640x480 logical imageへdecodeした。画面には
Rockbox main menuが表示されている。non-black ratioは0.876615、logical PNGの
SHA-256は次の通り。

```text
3bf995de7891e9f1c5fb0cafb26c819ec349512551e76d7e5c26670927d7ebcc
```

menu表示中はALSA playback streamを開かなかったため、この試験は起動と表示の合格を示し、
音楽再生の証拠とはしない。PortMaster正規stop helperでfrontend 1 processへ復帰した。
Rockbox、launcher、GPTokeYB2 process、tracking file、private mountはいずれも0となった。
終了後のdetached compatibility auditは203 ELF、error 0、既知の`LD_PRELOAD`置換warning
1件で完了した。最後の全Runtime検証も合格した。

再適用を防ぐため、実機専用transitionだけをdevice update inboxから削除した。host側の
証跡は`output/live/2026-08-30-pixel2-v0.1.4-device-update/`へ保持している。
