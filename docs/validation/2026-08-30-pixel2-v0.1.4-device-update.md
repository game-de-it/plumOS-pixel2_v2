The device ran the previously accepted PortMaster fix build rather than the
public v0.1.3 Runtime:


The public v0.1.3-to-v0.1.4 package was not forced onto this development
Runtime. The device checksum index was read back and used to build an exact,
device-only signed transition to the formal v0.1.4 app layer.


The package was verified locally, transferred under a hidden temporary name,
hashed on the device, synced, atomically renamed, hashed again, and accepted by
the production updater. The normal safe-reboot path stopped the frontend and
cleanly unmounted `/roms` and the user volume before rebooting.

## Rockbox validation

`/mnt/plumos-user/roms/PORTS/Rockbox.sh` was launched through the production
`plumos-portmaster-port-launch` path. The launcher, Rockbox, and GPTokeYB2
processes started while the frontend released display ownership.

The active DRM plane was captured and decoded to a correctly oriented 640x480
logical image. It visibly shows the Rockbox main menu. Its non-black ratio was
0.876615 and the logical PNG SHA-256 is:

```text
3bf995de7891e9f1c5fb0cafb26c819ec349512551e76d7e5c26670927d7ebcc
```

The menu did not open an ALSA playback stream, so this test establishes launch
and display behavior rather than music playback. The normal PortMaster stop
helper returned to one frontend process. Rockbox, launcher, and GPTokeYB2
processes, tracked files, and private mounts all returned to zero. The detached
compatibility audit completed for 203 ELF files with zero errors and one known
`LD_PRELOAD` replacement warning. A final full Runtime verification passed.

The exact device-only transition was then removed from the device update inbox
to prevent accidental reapplication; the host evidence copy remains under
`output/live/2026-08-30-pixel2-v0.1.4-device-update/`.
