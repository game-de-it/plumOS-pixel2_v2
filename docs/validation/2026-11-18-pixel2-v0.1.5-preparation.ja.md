# Pixel2 v0.1.5配布物の準備

[English](2026-11-18-pixel2-v0.1.5-preparation.md)

新規SD image、対応source、公開v0.1.4用の署名Runtime updateを生成し、配布用updateを
実機へ適用して検証する。GitHub公開は今回の対象外。

v0.1.4以後の変更はhardware-key daemon、RetroArch patch 037/038、testsとdocs。
frontendとRetroArchは通常scriptで再buildし、その他はsource/recipe差分とchecksumを
確認した変更なしのv0.1.4 componentを再利用する。未再build componentの元のsource
manifestは維持する。既存scriptでRuntime/System/SD imageを生成し、strict gateと
連続2回のSD image SHA一致を要求する。

公開updateの基点として、v0.1.4 app layerを
`output/release-base/v0.1.4/plumos`へ保持する。checksum indexのSHA-256は
`abbf3236cba85b6e31d9aae8e2c5f1b57b0c0f091ebeddc5e350536db70efec1`。
stock boot/kernel/DTBと初回User partition生成を維持し、新規SDの実機bootは
今回依頼されたlive updateとは別のoperator確認項目とする。

実機ではlive patch差分が配布updateで収束するか確認し、設定・save・BIOS・ROM・
PortMasterをhash/countで記録。署名検証、一時名転送、実機hash、sync、atomic rename後の
再検証を経て、production updaterとsafe rebootを使う。更新後は0.1.5、source、
transaction healthy、pendingなし、全checksum、FE/Wi-Fi、mutable snapshot保持を確認する。
変更した電源メニュー復帰・整数スケールも再確認し、機械/capture確認とLCD目視は区別する。

## 実機アップデート

公開v0.1.4 treeのfixtureへ同じ配布packageを適用し全checksumを検証。
実機の限定live patchとの差分もpackageで収束することを確認し、forceなしで更新した。
updateは11 fileを更新、古い`apps/.DS_Store`があれば除去する（今回の実機にはなかった）。

実機転送前後のhash一致、署名・ABI・source version検証、atomic rename、request、
safe rebootを実行。operatorは更新画面とFE復帰を確認した。
transactionは`previous_version=0.1.4`、`version=0.1.5`、`status=healthy`、
最終結果は`runtime_healthy`。pending/requestはなく、管理11,334件の検証に合格。
root checksum indexとfrontend/RetroArch binaryは配布用treeと一致。

Runtimeだけの更新なので既存のSystem表示は0.1.4のままが正常。新規SD imageでは
Systemも0.1.5。stock kernel/DTB/boot経路は変更していない。

更新前後267 fileをhash比較。ROM 248件・mutable設定19件を保持した。
BIOS、save、stateは各0件のため、既存save内容の保持試験とはしない。
265件はbyte不変。`network/services.conf`は行順のみ変化し、旧hashが現在の行の
並べ替えと完全一致することで設定値保持を証明。`wpa_status.txt`は起動時の接続状態記録。
Wi-Fi資格情報とRetroArch cfgはbyte不変。ユーザーデータを配布metadataへ合わせる
上書きはしていない。

## 更新後の描画・復帰

QuickNES／256x224／Core Provided／Axis Y整数ONを一時append設定で比較した。
RGUI、Ozone、XMB、GLUIのgame→menu→カーソル移動→gameをscanout capture。
menuの向き・全面表示・カーソル移動を画像確認し、game前後は各224組中224組の
隣接2行が一致、非自明な行間変化も存在。縦224→448の実pixel倍化を確認した。
RGUI planeはphysical `16,27,448,586`、logical中央586x448。

POWER表示→Bを3回実行し、両planeのCRTC/SRC全座標が前後一致した。
4経路ともALSA RUNNINGで1秒間のhw_ptr進行を確認。保存済みRA cfg hashは
`37a45c081482ab23bf8fbba159717295eb1a6bbde084eeab3cb219e84676eefc`を保持。
試験終了後はFEへ復帰し、Wi-Fi接続とRuntime healthyを再確認した。

初回の一時testは再起動で消えるaudio/udev準備を省略していたため、menu試験の
合格証拠から除外。通常launcherと同じ`plumos-audio-output prepare`と
`plumos-ensure-udev-input-db`を実行して全試験を取り直した。製品codeの追加変更はない。

証跡は`output/release-v0.1.5/logs/`、`pre/`、`post/v015-proof/`。
ROMを含むcapture、機器の設定内容などは配布物へ含めていない。
新規SD自体のphysical boot、LCD上の最終目視、音の聴感はこの機械検証とは別の確認。
この完了記録のcommitは固定source以後のdocs/TODOだけで、配布binaryの変更はない。
