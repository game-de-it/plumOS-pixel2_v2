# Pixel2 v0.1.5 artifact preparation

[日本語](2026-11-18-pixel2-v0.1.5-preparation.ja.md)

## Scope and inputs

Prepare a new-card image, exact source archive and signed v0.1.4-to-v0.1.5
Runtime update. Apply the distribution update on the Wi-Fi-connected Pixel2
and read back the resulting managed files and mutable-state preservation.
Publication is outside this task.

The changes since tag v0.1.4 are the hardware-key daemon, RetroArch patches
037/038, tests and validation documents. Rebuild the frontend and RetroArch
components through their normal build scripts, retaining their source manifests.
Retain unchanged v0.1.4 core/application components only after checksum and
recipe/source-change review; do not relabel them as rebuilt. Assemble Runtime,
System and compact SD image through the existing Pixel2 scripts. Run strict
release gates and two consecutive SD assemblies with identical output hashes.

The retained v0.1.4 app layer at
`output/release-base/v0.1.4/plumos` is the distribution update baseline, with
checksum-index SHA-256
`abbf3236cba85b6e31d9aae8e2c5f1b57b0c0f091ebeddc5e350536db70efec1`.
The fresh image retains exact stock boot/kernel/DTB inputs and first-boot User
partition provisioning. Fresh-card physical boot remains a separate operator
acceptance from the requested live update test.

## Intended device checks

- Verify that any installed live-patch differences are either included in the
  public delta or already identical to the final Runtime; use no forced bypass.
- Snapshot mutable config/save/BIOS/ROM/PortMaster data using counts/hashes.
- Verify signature and package payload, transfer under a hidden temporary name,
  verify remote SHA-256, sync, atomic rename and verify again.
- Request the package through the production updater and safe reboot.
- Confirm Runtime 0.1.5, source provenance, healthy transaction, no pending state,
  complete managed checksums, FE/Wi-Fi and preservation of the mutable snapshot.
- Recheck the power-menu return and integer-scaling routes in proportion to the
  changed code; keep machine/capture checks separate from physical LCD acceptance.

## Real-device update

The same distribution package passed an update simulation on the public v0.1.4
tree and a convergence audit against the device's scoped live patches. No forced
updater bypass was used. The delta updates 11 files and deletes obsolete
`apps/.DS_Store` if present (absent on this device).

Transfer/readback hashes, signature, ABI and source-version checks passed before
atomic rename, production update request and safe reboot. The operator observed
the update screen and frontend return. The transaction records 0.1.4 to 0.1.5,
status `healthy`; last result is `runtime_healthy`, with no request/pending state.
All 11,334 managed checksums passed. Root checksum index and frontend/RetroArch
binaries match the distribution tree exactly.

This Runtime-only update intentionally retains installed System 0.1.4; the fresh
SD contains System 0.1.5. Stock kernel/DTB/boot behavior is unchanged.

Compared 267 mutable-file hashes before/after: 248 ROM files and 19 settings
files retained. BIOS/save/state counts were zero, so this is not a populated
save-preservation acceptance. 265 hashes were unchanged. `network/services.conf`
changed only line order, proven by a permutation matching its exact previous
hash. `wpa_status.txt` is regenerated connection status. Wi-Fi credentials and
RetroArch config remained byte-identical. User data was not overwritten to
match host metadata.

## Post-update display and recovery

QuickNES 256x224, Core Provided, integer Axis Y was checked with temporary append
configs for RGUI/Ozone/XMB/GLUI. Scanout captures show each menu, cursor movement
and game return. Each before/after game capture has 224/224 matching adjacent
row pairs and nontrivial differences between source rows: actual 224-to-448
pixel doubling. RGUI plane geometry is physical `16,27,448,586`, logical centered
586x448.

Three POWER-to-B cycles preserved every CRTC/SRC coordinate on both planes.
All four paths had ALSA RUNNING with hw_ptr advancing over one second. The saved
RetroArch config retained SHA-256
`37a45c081482ab23bf8fbba159717295eb1a6bbde084eeab3cb219e84676eefc`.
The frontend, Wi-Fi and healthy Runtime were confirmed again at test completion.

The initial temporary harness omitted volatile audio/udev preparation after
reboot and is excluded as menu acceptance evidence. All checks were repeated
after the normal launcher's `plumos-audio-output prepare` and
`plumos-ensure-udev-input-db`; no further product-code change was necessary.

Evidence: `output/release-v0.1.5/logs/`, `pre/`, `post/v015-proof/`. Captures
containing game material and device settings are not distribution assets.
Fresh-card physical boot and final LCD/listening acceptance remain separate
from these machine checks. The completion commit changes only docs/TODO after
the frozen source, not distribution binaries.

## GitHub publication

On 2026-11-18, after disclosure of the verified Runtime update and the untested
fresh-card physical boot, the operator explicitly requested GitHub publication.
The bilingual notes retain that limitation rather than claiming a fresh-card
hardware acceptance. No artifact was rebuilt. Annotated tag `v0.1.5` points to
the manifest's exact `b03d294` source; subsequent documentation commits are on
main only and the release tag is not moved.

[plumOS Pixel2 v0.1.5](https://github.com/game-de-it/plumOS-pixel2_v2/releases/tag/v0.1.5)
was published as a normal Latest release with seven assets: SD 7z, source,
signed Runtime update, update checksum, manifest, bilingual notes and SHA256SUMS.
Draft verification checked every GitHub asset size/digest, exact note body and
tag/source identity before publication.

All seven assets were then downloaded from unauthenticated public URLs and
passed the existing verifier: checksums, manifest, 7z integrity, uncompressed
image size/hash and source archive. Result: `release_redownload=result-ok assets=7`.
The Latest API reports `v0.1.5`, draft/prerelease=false. The source archive's Git
commit ID and remote tag target both match `b03d294`.

Publication evidence: `output/release-v0.1.5/logs/github-{draft,published}.json`
and `github-redownload-verify.log`.
