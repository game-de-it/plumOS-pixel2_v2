# Pixel2 ADB host-disconnect recovery

Date: 2026-08-19

## Failure boundary

The reconciled USB owner build kept ADB and Wi-Fi mutually exclusive, but it
did not restore a transport after the USB host disappeared. The physical
device used the same `adbd` binary as the previously accepted `45b4505`
Runtime. ADB 35 and 36, both macOS USB backends, and a newly generated USB
serial all failed at the first `CNXN`. The macOS endpoint error remained
`kIOReturnNotResponding`, so neither the host ADB version nor the host's
per-device cache explained the failure.

A macOS restart gave the decisive boundary. Before restart, macOS had selected
configuration 1 and exposed the ADB interface and both bulk endpoints. After
restart, the same powered Pixel2 exposed only the parent device:

```text
product:       plumOS Pixel2 ADB
VID:PID:       18d1:4ee7
speed:         480 Mbps
configuration: 1
serial:        plumos-pixel2-55f69261f5f64c54
ADB interface: absent
adb devices:   empty
```

This is a device-side FunctionFS recovery failure after a real host disconnect,
not an FE status, cable, macOS cache, or Wi-Fi ownership failure.

## Lifecycle defect

Runtime inspection over Wi-Fi found a second, deterministic defect. The ADB
monitor PID file held the parent shell PID while the actual background monitor
had the next PID. `USB Mode = Wi-Fi` therefore could not stop the monitor, and
the surviving process could restart ADB while Wi-Fi owned the only OTG port.
Commit `662cace` records the exact child PID and makes all three USB modes stop
or start that process explicitly.

## V90S-aligned recovery

V90S commits `d1721a9` and `e2fe3c3` use BusyBox's blocking `uevent` listener
instead of a timer. Pixel2 now follows the same contract:

- accept only `SUBSYSTEM=android_usb` and `USB_STATE=DISCONNECTED`;
- recheck that persistent `usb_mode=adb` is still selected after a one-second
  settle period;
- retain a healthy `adbd` process and its FunctionFS endpoints;
- unbind and rebind the Pixel2 configfs UDC exactly once;
- coalesce duplicate events and suppress only the disconnect generated by that
  explicit self-rebind;
- stop the listener before Wi-Fi or Off takes ownership.

Pixel2 needs an explicit UDC rebind because its configfs `UDC` attribute can
remain bound after the host disappears. This is the only hardware-specific
difference from the V90S event contract. There is no boot timer, transport
offline timer, endpoint polling loop, or recurring restart loop.

The implementation is commit `d7142ac`.

## Host verification

```text
pixel2_adbd_recovery=result-ok source=v90s-event-driven mode=single-replug
pixel2_usb_mode=result-ok
pixel2_usb_host_reenumerate=result-ok
pixel2_network_control=result-ok
pixel2_wifi_recovery=result-ok
system_rootfs_scripts=result-ok
```

The recovery fixture also verifies that the PID file belongs to the live
BusyBox uevent listener and that an explicit stop terminates that exact PID.

## Physical acceptance still required

The signed System and Runtime must be applied as one compatible update set.
Acceptance requires all of the following, using a real shell rather than FE
status alone:

1. cold boot with USB Mode ADB reaches `adb shell`;
2. cable removal and insertion restores the shell without rebooting Pixel2;
3. a macOS host restart restores the shell without rebooting Pixel2;
4. switching to Wi-Fi leaves no adbd or ADB uevent listener;
5. switching back to ADB stops Wi-Fi ownership and restores a shell.
